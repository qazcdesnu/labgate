# 작업 목록

labgate 프로젝트에서 일어나는 모든 작업을 **누가, 무엇으로, 무엇을 바꾸는가**로 나열한다. 에이전트 규칙(일반 규칙, 절차의 특별 규칙)과 도구는 이 표를 근거로 정한다.

- 사람이 하는 일의 안내: [사용자 작업 설명서](guide/README.md)
- 명령의 세부: [명령 설명서](cli/README.md)
- 규칙과 도구의 사양: [설계 문서](../labgate-design.md) §16, §17, §21

## 판정 기준

1. 작업이 일반 규칙이 금지한 것을 해야 하는가? 아니면 특별 규칙이 필요 없다.
2. 해야 한다면, 그 일을 **정확하게 검증·실행할 수 있는가**? 그렇다면 도구로 만든다. 도구가 하는 일은 도구의 명세와 테스트로 정하고 특별 규칙을 두지 않는다.
3. 판단이 필요한 일(사람의 말을 문서로 옮기기, 내용을 보고 타입 고르기)만 절차의 특별 규칙으로 허용한다.

## 사람에서 에이전트로 넘어가는 지점

[사용자 작업 설명서](guide/README.md#사람에서-에이전트로-넘어가는-지점)의 H1–H7이 어느 작업으로 이어지는지.

| 지점 | 사람이 남기는 것 | 이어받는 작업 | v0.2 | v0.3 |
|---|---|---|---|---|
| H1 | `plan` + `Approve` | O7 | **절차에 없음** (에이전트 판단) | 도구가 카드 `draft → approved` |
| H2 | `gate` | O7 | `gate-apply` (에이전트가 편집) | 도구 |
| H3 | `respond` | O7 | `gate-apply` (에이전트가 편집) | 도구 |
| H4 | `decide` | O7 | **절차에 없음** (에이전트 판단) | 도구가 결정 `→ confirmed` |
| H5 | `plan`·`spec` (계획·사양 변경) | — | 에이전트가 다음 작업부터 따름 | 그대로 (반영할 상태 필드 없음) |
| H6 | 커밋하지 않은 사람의 변경 | O3 → O5 | `session-check` + `commit-prep` | 그대로 |
| H7 | 대화로 전한 판정·결정·응답 | O6 → (사람 O2) → O7 | `gate-conversation`이 상태도 편집 | 응답만 쓰고, 상태는 사람 커밋 뒤 도구가 |

## 결론

- 특별 규칙은 세 곳에만 남는다: `commit-prep`(G2), `gate-conversation`(G5), `gate-apply`(G4·G6: 도구가 만든 전이만 커밋).
- `session-start`는 특별 규칙이 없어진다. 기록·정리는 `session-check`가 한다.
- 상태 전이 반영(O7)은 경로가 하나가 된다. 문서로 판정하든 대화로 판정하든, 사람이 커밋한 뒤 같은 도구가 반영한다.
- 이 표에 작업이 추가되면(예: ideation 절차) 같은 기준으로 특별 규칙과 도구를 정한다.
