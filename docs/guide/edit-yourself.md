# 내가 직접 고쳤을 때

- 언제: 실험 코드, 결과 문서, 노트 등을 사람이 직접 고쳤을 때
- 결과: 그 변경이 **사람 신원의 커밋으로, 에이전트 작업보다 먼저** 남는다. 에이전트의 커밋에 섞이지 않는다

사람의 변경은 사람이 커밋한다. 에이전트는 사람의 변경을 자기 커밋에 넣거나, 되돌리거나, 치우지 않는다. 사람이 쓸 수 있는 타입은 사람 전용(`gate`, `decide`, `plan`, `spec`, `respond`)과 공통(`exp`, `run`, `result`, `ref`, `log`, `chore`)이다.

## 순서

### 경우 1: 세션 밖에서 고쳤다 (가장 간단)

에이전트 세션을 시작하기 전에 터미널 A에서 커밋한다.

```bash
lg commit
```
질문: 커밋할 파일(스페이스로 선택) → 타입(실험 코드면 `exp`, 결과 문서면 `result`, 노트면 `chore` …) → 필요하면 Task → 요약 → 커밋.

### 경우 2: 커밋하지 않고 세션을 시작했다

세션이 시작될 때 `scripts/session-check`가 "커밋되지 않은 사람의 변경"을 알리고, 에이전트가 작업 전에 선택지를 준다. 하나를 고른다.

| 선택 | 하는 일 |
|---|---|
| 1. 직접 커밋 | 터미널 A에서 `lg commit` 후 에이전트에게 알린다 |
| 2. 초안 부탁 | 에이전트가 변경을 읽고 `lg draft`로 초안을 만든다. 터미널 A에서 `lg commit`으로 확인·확정하고 알린다 |
| 3. 직접 정리 | 이어서 고치거나 버린다(`git restore <파일>`은 사람이 직접). 끝나면 알린다 |

### 경우 3: 세션 도중에 고쳤다

세션 도중의 변경은 자동으로 감지되지 않는다(세션 시작 시점만 본다). 에이전트에게 고친 파일을 알린다.

> experiments/src/loader.py를 내가 고쳤어. 커밋 준비해 줘.

에이전트가 자기 변경을 먼저 커밋하고, 알려 준 경로로 `lg draft`를 만든다. 터미널 A에서 `lg commit`으로 확정한다.

## 확인

```bash
git log -1 --format='%an | %s'      # 나 | exp: …
git status --short                  # 남은 변경이 없어야 한다
```

## 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| 에이전트가 "한 파일에 사람과 에이전트의 변경이 섞였다"며 멈춤 | 같은 파일을 둘이 고쳤다. 어느 쪽으로도 정확히 커밋할 수 없어서 멈춘 것이다. `git diff <파일>`을 보고 직접 정리하거나 지시한다 |
| `lg draft`가 "stage된 다른 변경이 있습니다" | 에이전트가 stage해 둔 변경이 있다. 에이전트가 먼저 커밋해야 한다 |
| 내 변경이 에이전트 커밋에 들어갔다 | 규칙 위반이다. 되돌리는 법은 [mistakes.md](mistakes.md) |
| `exp`를 골랐는데 `'exp'는 에이전트 타입입니다` | labgate 0.1로 만든 프로젝트다. `chore`를 쓰거나 규칙 문서를 갱신한다 ([upgrade.md](upgrade.md)) |

## 에이전트는 무엇을 하나

- 세션 시작 점검: `scripts/session-check`, `specs/procedures/session-start.md`
- 커밋 준비: `specs/procedures/commit-prep.md`
- 초안 명령: [lg draft](../cli/lg-draft.md)
