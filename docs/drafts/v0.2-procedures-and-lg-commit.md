## 1. 목적

1. **규칙을 두 층으로 나눈다.** 매 세션 읽는 일반 규칙(`AGENTS.md`)은 짧은 불변 규칙만 담고, 특정 상황에서만 필요한 절차는 그때 읽는 절차 문서(`specs/procedures/`)로 뺀다.
2. **사람의 변경을 어느 경로로 시작하든 같은 결과로 정리한다.** 결과는 항상 "사람의 변경이 사람 신원의 커밋으로, 에이전트 작업보다 먼저 남는다"이다.
3. **사람 쪽 확정 동작을 `lg` 명령으로 모은다.** 에이전트 쪽 절차와 사람 쪽 `lg` 명령을 짝지어, 명령마다 동작 방식이 같게 한다.

## 2. 범위

| 포함 | 제외 (이후) |
|---|---|
| 절차 문서 구조, `AGENTS.md`·`workflow.md` 재구성 | `lg gate` (이 구조 위에 만든다) |
| `lg commit` (사람 전용, 대화형 확정) | `lg status`, `lg validate`, `lg upgrade` |
| `lg draft` (사람 커밋의 초안 준비, 에이전트도 사용) | 세션 도중 사람 변경의 자동 감지 (§9) |
| Claude Code SessionStart hook, 권한 규칙 | 다른 에이전트 도구의 hook 연결 |
| `spec_version` 2 | 0.1 프로젝트 자동 이전 |

## 3. 확정할 설계 결정

| 항목 | 결정 |
|---|---|
| 규칙 층 | 일반 규칙은 언제나 지켜야 하는 불변 규칙만. 절차는 시작 조건이 있을 때만 읽는다 |
| 예외의 표기 | 절차가 일반 규칙을 푸는 경우, 일반 규칙 쪽에 "예외: 절차 X" 한 줄, 절차 쪽에 "푸는 규칙: N번" 한 줄. 양쪽에 적어 모순으로 읽히지 않게 한다 |
| 사람 신원의 커밋 | 사람만 만든다. 에이전트는 `lg commit`, `git commit`을 실행하지 않는다 |
| 에이전트가 할 수 있는 최대치 | stage와 메시지 초안 작성(`lg draft`)까지. 확정은 사람이 `lg commit`으로 한다 |
| 확정의 조건 | `lg commit`은 표준 입력과 출력이 모두 터미널(TTY)일 때만 커밋한다 |
| 감지 | 세션 시작 시 커밋되지 않은 변경을 자동 감지해 에이전트 맥락에 넣는다 (Claude Code SessionStart hook). 다른 도구는 `AGENTS.md` 세션 시작 절차로 같은 확인을 한다 |
| 규칙의 원본 | 타입·trailer 규칙은 프로젝트의 `.lg/hooks/commit-msg`가 원본이다. `lg`는 그 파일에서 상수를 읽고, 최종 검증은 커밋 시 hook에 맡긴다 |
| `lg`의 위치 | 편의 도구다. `lg` 없이 `git commit`으로 커밋해도 hook을 통과하면 유효하다 |
| 사람 변경의 범위 | 세션 시작 시 `scripts/session-check`가 커밋되지 않은 파일 목록을 `.lg/pending/HUMAN_FILES`에 기록한다. `lg draft`의 경로 생략형은 이 목록만 stage한다 |
| `gate` 커밋 | v0.2에서는 `lg commit`이 받는다(초안 모드, tag 포함). `lg gate`가 생기면 `gate` 타입은 `lg gate`로 옮기고 `lg commit`은 안내와 함께 거부한다 |
| 감지의 도구 중립성 | `scripts/session-check`는 도구와 무관한 스크립트다. Claude Code는 SessionStart hook으로 자동 실행하고, 다른 도구는 `session-start` 절차의 첫 단계로 실행한다 |
| 절차 문서 위치 | `specs/procedures/`. `specs/`처럼 사람만 수정한다 |

## 4. 규칙 구조

### 4.1 원칙

- **일반 규칙**(`AGENTS.md`): 어떤 작업 중이든 지켜야 하는 것. 위반하면 기록이 틀어지는 것(신원, 타입, 사람의 변경, 금지 목록)과 멈춰야 하는 조건.
- **절차**(`specs/procedures/<name>.md`): 시작 조건이 있는 단계 목록. 시작 조건은 사람의 요청, 슬래시 명령, 세션 시작·종료, 감지 결과 중 하나.
- 절차는 일반 규칙을 **좁게** 풀 수 있지만 넓힐 수는 없다. 예: `commit-prep`은 "사람의 변경을 stage하지 않는다"를 풀지만, 사람 신원 커밋 금지는 풀지 못한다.

### 4.2 절차 목록

| 절차 | 시작 조건 | 짝 `lg` 명령 (사람) | Claude Code 명령 | 기존 위치 |
|---|---|---|---|---|
| `session-start` | 세션 시작 (첫 단계: `scripts/session-check` 실행) | — | `/session-start` | AGENTS.md 세션 시작 절차 |
| `session-close` | 세션 종료 | — | `/session-close` | AGENTS.md 세션 종료 절차 |
| `task-start` | 승인된 task 착수 | — | `/task-start` | workflow §5.1 |
| `task-gate` | task 완료, 게이트 요청 | `lg gate` (이후) | `/task-gate` | workflow §5 |
| `escalate` | 멈춤 조건 충족 | `lg commit` (`respond`) | `/escalate` | workflow §7 |
| `gate-conversation` | 사람이 대화로 판정 | `lg commit` | — | workflow §6.2 |
| `gate-apply` | 사람의 `gate` 커밋 이후 | — | — | workflow §6.3 |
| `commit-prep` | 커밋되지 않은 사람의 변경 감지, 또는 사람의 요청 | `lg commit` | `/commit-prep` | workflow §4.1 5번 |

### 4.3 절차 문서 형식

```markdown
---
id: commit-prep
type: procedure
spec_version: 2
---
# 사람 커밋 준비

- 시작 조건: <언제 이 문서를 읽는가>
- 푸는 일반 규칙: AGENTS.md 규칙 <N> (<무엇을 허용하는가>) — 없으면 "없음"
- 끝나는 상태: <절차가 끝났을 때 작업 트리·문서 상태>

## 단계
1. ...

## 멈추는 경우
- ...
```

### 4.4 `AGENTS.md` 새 구성 (요지)

```
# 에이전트 작업 규칙
## 프로젝트            (이름, 연구 질문, 에이전트 신원)
## 역할                (2줄)
## 반드시 지킬 규칙     (불변 규칙만, 아래)
## 절차                (상황 → 절차 문서 표)
## 참고
```

불변 규칙 (현재 10개 + 세션 절차 → 7개 정도):

1. 문서는 `specs/`의 사양을 따른다.
2. 커밋은 `scripts/agent-commit`으로만 한다. `git commit`, `lg commit`을 실행하지 않는다. `--no-verify`, `--author`, `-a`를 쓰지 않는다. trailer는 마지막 한 문단.
3. 사람 전용 타입(`gate`, `decide`, `plan`, `spec`, `respond`)을 쓰지 않는다.
4. 자기가 바꾼 파일만 경로를 지정해 stage한다. 사람의 변경은 stage·커밋·되돌리기 하지 않는다. 예외: 절차 `commit-prep`.
5. 금지 목록 (상태 변경, 사양·규칙 파일 수정, tag, 이력 재작성, 병합). 예외: task 카드 "범위 › 포함", 절차 `gate-conversation`, `gate-apply`.
6. 멈추고 에스컬레이션할 조건 (범위 밖, 미확정 결정, 예산 초과). 절차 `escalate`.
7. 본문 한국어, 사실과 추측 구분.

절차 표:

| 상황 | 읽을 문서 |
|---|---|
| 세션 시작 | `specs/procedures/session-start.md` |
| 커밋되지 않은 사람의 변경이 있음, 또는 사람이 커밋 준비를 요청 | `specs/procedures/commit-prep.md` |
| ... | ... |

### 4.5 `workflow.md` 축소

원칙(§1), 역할(§2), 상태 기계(§3), 게이트 판정별 다음 단계(§6.4)만 남긴다. 단계 목록(§4.1, §5, §6.1–6.3, §7)은 절차 문서로 옮긴다. 다른 문서의 `workflow.md §N` 참조는 절차 문서 링크로 바꾼다.

## 5. 사람의 변경: 세 가지 시작 경로, 한 가지 결과

```
A. 사람이 먼저 정리       사람: 수정 → lg commit ─────────────────────────────┐
                                                                             │
B. 감지 → 사람이 직접     세션 시작 → hook이 감지 → 에이전트 멈춤, 선택지 제시   │
                          → 사람: lg commit ──────────────────────────────────┤
                                                                             ├─▶ 사람 신원 커밋
C. 감지 → 초안 → 확정     세션 시작 → hook이 감지 → 에이전트: lg draft          │    → 에이전트 작업 시작
                          → 사람: lg commit (초안 확인 후 확정) ───────────────┘

   (B·C에서 사람이 "버린다"를 고르면 사람이 직접 git restore. 에이전트는 되돌리지 않는다.)
```

에이전트가 감지 후 제시하는 선택지 (`commit-prep` 절차):

1. 직접 커밋: 터미널에서 `lg commit`
2. 초안 준비: 에이전트가 `lg draft` → 사람이 `lg commit`
3. 이어서 수정하거나 버림: 사람이 처리한 뒤 알려 줌

사람이 답할 때까지 에이전트는 다른 작업을 하지 않는다. 세션 시작 절차의 다른 단계(읽기)는 계속해도 된다.

## 6. `lg commit` 사양

### 6.1 형식

```
lg commit [--pending | --no-pending] [--yes-tag | --no-tag]
```

| 옵션 | 설명 |
|---|---|
| (없음) | `.lg/pending/COMMIT_MSG`가 있으면 초안 모드, 없으면 대화형 작성 모드 |
| `--pending` | 초안 모드를 강제. 초안이 없으면 코드 3 |
| `--no-pending` | 초안이 있어도 무시하고 대화형 작성 (초안 파일은 그대로 둔다) |
| `--no-tag` | 초안 모드에서 `gate` + `Verdict: approve`여도 tag를 만들지 않는다 |

### 6.2 동작 순서

1. **저장소 확인.** Git 저장소 루트와 `.lg/project.yaml`을 찾는다. 없으면 코드 2 ("labgate 프로젝트가 아닙니다").
2. **버전 확인.** `.lg/project.yaml`의 `spec_version`이 이 `lg`가 아는 범위가 아니면 코드 2 (업데이트 안내).
3. **TTY 확인.** 표준 입력·출력이 터미널이 아니면 코드 2. 메시지: "lg commit은 사람이 터미널에서 직접 실행합니다. 에이전트는 lg draft로 초안만 준비합니다."
4. **신원 확인.** `git config user.email`이 `.lg/identities.json`의 humans에 없으면 코드 2.
5. **규칙 읽기.** `.lg/hooks/commit-msg`를 모듈로 읽어(`runpy.run_path`, `__main__`이 아닌 이름) `HUMAN_TYPES`, `AGENT_TYPES`, `COMMON_TYPES`, `TASK_REQUIRED`, `SOURCE_REQUIRED`를 가져온다. 사람이 쓸 수 있는 타입 = 사람 전용 ∪ 공통.
6. **모드별 메시지 준비.** §6.3 / §6.4.
7. **확인.** staged diff 통계(`git diff --cached --stat`)와 최종 메시지를 보여 주고 확정 / 편집기로 수정 / 취소를 묻는다.
8. **커밋.** `git commit -F <임시 파일>`. hook이 거부하면 hook의 출력을 그대로 보여 주고 코드 4. 초안 모드에서는 초안 파일을 남긴다.
9. **정리.** 초안 모드면 초안 파일과 `.lg/pending/HUMAN_FILES` 삭제. `gate` + `Verdict: approve`면 tag `gate/<Task>` (`--no-tag` 제외), `Milestone-Verdict`가 있으면 `milestone/<M>-<verdict>`도.
10. **출력.** 커밋 해시, 만든 tag, 에이전트에게 알릴 한 줄("커밋했습니다: <해시>").

### 6.3 대화형 작성 모드

1. stage된 변경이 없으면 변경된 파일 목록(추적 중 수정, 새 파일)을 보여 주고 체크박스로 고르게 해 stage한다. 아무것도 고르지 않으면 코드 3.
2. 타입: 사람이 쓸 수 있는 타입만 선택지로.
3. scope와 필수 trailer: 타입이 `TASK_REQUIRED`면 Task ID를 `plan/milestones/*/tasks/*.md` 목록에서 고른다. `SOURCE_REQUIRED`면 `document | conversation`. `gate`면 `Verdict`, 선택 `Next`, `Milestone-Verdict`. `decide`면 `Decisions`.
4. 요약 한 줄(헤더 72자 검사), 본문(선택, 편집기).
5. `Actor: human`은 자동.

### 6.4 초안 모드

1. 초안 파일을 읽는다. staged 변경이 없으면 코드 3 ("초안은 있는데 stage된 변경이 없습니다").
2. `Actor: human`이 아니면 코드 2 (초안이 사람 커밋용이 아님).
3. §6.2의 7단계로 간다.

### 6.5 종료 코드

`lg init`과 같은 체계를 쓴다.

| 코드 | 의미 |
|---|---|
| 0 | 커밋 성공 |
| 1 | 예기치 못한 실행 오류 |
| 2 | 사용법·환경 오류 (TTY 아님, 신원 미등록, labgate 프로젝트 아님, 모르는 spec_version, 초안이 사람 커밋용 아님) |
| 3 | 커밋할 것 없음 (stage 없음, 초안 없음) |
| 4 | Git 오류 (hook 거부 포함, tag 실패) |
| 130 | 사용자가 취소 |

## 7. `lg draft` 사양

사람 커밋의 초안을 준비한다. 커밋하지 않는다. 에이전트와 사람 모두 쓸 수 있다.

### 7.1 형식

```
lg draft --type T [--scope S] --summary TEXT [--body TEXT] [--trailer KEY=VALUE ...] [PATH ...]
```

- `PATH`를 주면 그 경로만 stage한다. 세션 도중 사람이 알려 준 변경처럼 감지 목록에 없는 경우에 쓴다.
- 생략하면 `.lg/pending/HUMAN_FILES`(세션 시작 시 `session-check`가 기록한 사람의 변경)에 있는 경로만 stage한다. 이 파일이 없으면 코드 2 ("경로를 지정하세요"). 커밋되지 않은 모든 변경을 stage하는 형태는 두지 않는다. 세션 도중에 쓰면 에이전트의 변경까지 사람 커밋에 섞이기 때문이다.
- `Actor: human`은 자동으로 넣는다. `--trailer Actor=...`는 거부.

### 7.2 동작

1. `lg commit` §6.2의 1, 2, 5단계.
2. 초안 파일이 이미 있으면 코드 3 (사람 커밋 대기 상태).
3. 타입이 사람이 쓸 수 있는 타입인지, 필수 trailer가 있는지, 헤더 길이를 검사한다. 실패 시 모든 오류를 모아 코드 2. (신원 검사는 하지 않는다. 커밋할 때 hook이 한다.)
4. stage한다. 그 결과 stage된 변경이 없으면 코드 3.
5. `.lg/pending/COMMIT_MSG`에 메시지를 쓴다.
6. 사람에게 전할 안내를 출력한다: "터미널에서 `lg commit`을 실행하세요. stage된 변경: N개 파일".

### 7.3 종료 코드

`lg commit`과 같다 (130 제외).

## 8. Claude Code 연결

### 8.1 SessionStart hook

`.claude/settings.json`에 추가:

```json
"hooks": {
  "SessionStart": [
    {
      "hooks": [
        { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/scripts/session-check" }
      ]
    }
  ]
}
```

- matcher를 생략해 새 세션, 재개, `/clear`, compact 모두에서 실행한다. compact와 `/clear` 뒤에도 맥락을 다시 넣어야 하기 때문이다.
- SessionStart hook은 세션을 막을 수 없다(종료 코드와 무관). 이 hook의 역할은 알리는 것이고, 멈추는 것은 `AGENTS.md` 규칙과 `commit-prep` 절차가 한다.

`scripts/session-check` (Python 표준 라이브러리, `lg` 설치 불필요). 출력은 표준 출력의 일반 텍스트이고, 에이전트 맥락에 들어간다. 도구와 무관하게 쓸 수 있도록, `session-start` 절차의 첫 단계도 이 스크립트 실행이다(Claude Code에서는 hook이 이미 실행했으므로 출력만 다시 확인한다).

사람 커밋 대기 상태가 아니면, 커밋되지 않은 파일 목록을 `.lg/pending/HUMAN_FILES`에 한 줄에 하나씩 쓴다(작업 트리가 깨끗하면 이 파일을 지운다). 대기 상태에서는 파일을 건드리지 않는다. `.lg/pending/`은 Git 제외 대상이다.

| 상태 | 출력 |
|---|---|
| `.lg/pending/COMMIT_MSG` 있음 | "사람 커밋 대기 상태입니다. 커밋하지 말고 사람에게 `lg commit` 실행을 요청하세요 (procedures/gate-conversation.md 또는 commit-prep.md)." |
| 커밋되지 않은 변경 있음 | "커밋되지 않은 사람의 변경이 있습니다: <파일 목록, 최대 20개>. 작업 전에 specs/procedures/commit-prep.md를 따르세요." (목록 전체는 `.lg/pending/HUMAN_FILES`) |
| 깨끗함 | 출력 없음 |

### 8.2 권한 규칙

`deny`에 추가:

```
"Bash(lg commit *)"
```

- 끝의 ` *`는 옵션 없는 `lg commit`에도 일치한다.
- deny는 allow로 예외를 만들 수 없다(Claude Code 문서: deny → ask → allow 순서, 먼저 일치한 규칙이 결정). 그래서 준비 명령을 `lg commit --prepare`가 아닌 별도 이름 `lg draft`로 둔다. `Bash(lg commit *)`는 `lg draft`에 일치하지 않는다.
- 이 규칙도 실수 방지 장치다. 실제 장치는 §6.2의 TTY 확인이다.

### 8.3 슬래시 명령

- `/commit-prep` 추가: "specs/procedures/commit-prep.md를 따르라."
- 기존 명령(`/session-start` 등)은 본문을 절차 문서 한 줄 참조로 바꾼다.

## 9. 한계

1. **세션 도중의 사람 수정은 감지하지 못한다.** 감지는 세션 시작 시점의 작업 트리 기준이다. 세션 도중 사람이 고친 파일은 에이전트의 변경과 구분되지 않는다. 사용 규칙으로 둔다: "세션 도중에는 직접 수정하지 않는다. 했다면 에이전트에게 알리고, 에이전트는 `commit-prep`으로 간다." 자동 감지는 에이전트가 편집한 파일 목록을 기록하는 장치(PostToolUse hook 등)가 필요해 이후로 미룬다.
2. **TTY 확인은 보안 경계가 아니다.** 의사 터미널을 만드는 도구(`script` 등)로 우회할 수 있다. 규칙 위반을 의도하지 않은 에이전트의 실수를 막는 장치다. 이는 기존 `.claude/settings.json` deny와 같은 수준이다.
3. **Claude Code 프롬프트의 `!` 실행.** `! lg commit`이 TTY로 실행되는지 확인되지 않았다. TTY가 아니면 사람은 별도 터미널에서 실행해야 한다. 안내 문구에 반영한다.
4. **다른 에이전트 도구에는 자동 실행이 없다.** `session-start` 절차의 첫 단계에서 에이전트가 `scripts/session-check`를 직접 실행한다. 출력과 기록되는 파일 목록은 Claude Code와 같다.

### 10.2 `spec_version` 2

규칙 의미가 바뀌므로(공통 작업 타입, 사람의 변경, 절차 구조) 2로 올린다. `lg commit`, `lg draft`는 `spec_version` 2 프로젝트만 지원하고, 1이면 "v0.1 프로젝트입니다. git commit을 직접 쓰세요"로 코드 2. 0.1 프로젝트의 이전은 `lg upgrade`(이후)의 몫이다.

### 10.3 `lg`의 의존성

생성된 프로젝트의 필수 의존성은 그대로다(`git`, `python3`, `bash`). `lg`가 없으면 `git commit`으로 커밋하면 된다. `README.md`의 "저장소를 새로 클론했을 때"에 `lg` 설치를 권장 항목으로 추가한다.
